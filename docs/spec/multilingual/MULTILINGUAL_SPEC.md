# SPEC --- Мультиязычность сайта Talent Center DDC

## 1. Общая информация

-   **Проект:** Talent Center DDC / DDC NL
-   **Фича:** мультиязычность сайта (RU / NL / UK / EN)
-   **Тип:** сквозная инфраструктурная фича (затрагивает шаблоны, CPT,
    меню, формы, SEO)
-   **Локация бизнеса:** Нидерланды (юрлицо, KVK, VAT — см.
    `templates/agreement-template.php`)
-   **Основная аудитория:** русско- и украиноязычные родители/танцоры;
    английский добавлен как язык международной аудитории
-   **Статус:** зафиксированы требования и архитектурные решения
    (сессия `grill-with-docs`). Реализация не начата.

## 2. Цель

Сделать сайт доступным для русско-, украино-, нидерландско- и
англоязычной аудитории без потери текущего контента и без риска для
живого сайта, учитывая, что:

-   плагина мультиязычности сейчас нет;
-   весь текущий контент существует только на русском;
-   в теме уже есть один самодельный мультиязычный паттерн
    (`agreement-template.php`), который трогать не нужно.

## 3. Контекст и текущее состояние (факты)

-   Установленные плагины: `akismet`, `all-in-one-seo-pack` (AIOSEO),
    `w3-total-cache`. Плагина мультиязычности (Polylang/WPML/qTranslate)
    нет.
-   `language/` содержит только `nl_NL.po/.mo`; рабочего gettext-пайплайна
    для контента страниц нет — текст захардкожен в HTML шаблонов, без
    `__()`/`_e()`.
-   Кастомные типы записей (`includes/post-types.php`): `choreographer`,
    `styles`, `locations`, `team`, `faq`, `schedule`. Кастомные таксономии
    (`includes/taxonomies.php`): `team`, `choreographer`, `highlights`.
-   Шаблоны страниц (`templates/`, `page-templates/`): home, camp,
    contact, schedule, FAQ, styles, choreographers, sign-up, agreement,
    mailchimp-thank-you, а также legacy cart/checkout от WooCommerce
    (плагин WooCommerce сейчас не установлен).
-   Меню: `primary`, `footer_nav` (`register_nav_menus` в
    `functions.php`).
-   Заявки с форм уходят в Telegram (`TELEGRAM_TOKEN`/`TELEGRAM_CHAT_ID`)
    — см. термин "Contact Request" в `CONTEXT.md`.
-   `templates/agreement-template.php` уже реализует самодельную
    мультиязычность: весь текст EN/NL/RU лежит в одном DOM, JS
    переключает видимость через `data-lang`, выбор языка хранится в
    `localStorage` (`ddc_lang`), дефолт — `ru`.
-   Локальный MySQL на момент составления спеки не запущен — проверить
    фактическое состояние живого контента (язык, объём) можно только на
    продакшен-БД.

## 4. Языки и приоритет раскатки

| Язык | Роль | Статус на старте |
|---|---|---|
| RU | текущий дефолт, без префикса в URL | 100% контента уже существует |
| NL | следующий по приоритету, станет новым каноническим дефолтом | переводится вторым |
| UK | целевая аудитория | переводится третьим/четвёртым |
| EN | международная аудитория, полный паритет наравне с остальными | переводится третьим/четвёртым |

-   Полный паритет контента для NL/UK/EN — это финальная цель, а не
    ограниченный набор страниц.
-   RU остаётся дефолтным языком (без URL-префикса) до тех пор, пока NL
    не достигнет паритета по костяку страниц (см. раздел 7). После этого
    дефолт переключается на NL отдельным шагом.
-   Между NL, UK и EN порядок после NL не принципиален.

## 5. Технический механизм

-   **Polylang, бесплатная версия.** URL-структура — префикс языка
    (`/ru/`, `/nl/`, `/uk/`, `/en/`), RU как язык без префикса до
    переключения дефолта.
-   Причина выбора Free вместо Pro: нужная функциональность уже есть в
    Free —
    -   синхронизация featured image и custom fields между переводами
        (Languages → Settings → Synchronizations);
    -   автоматическая генерация hreflang-тегов в `<head>` (нужно только
        вручную выставить `x-default` на RU в Languages → Settings →
        Hreflang).
    -   Возможности Pro (встроенный DeepL в админке, "Synchronized
        posts", XLIFF) не нужны при выбранном workflow "MT-черновик вне
        WP + ручная вычитка" (см. раздел 10).
-   Слаги URL — **одинаковые во всех языках** (`/ru/schedule/`,
    `/nl/schedule/`, `/uk/schedule/`, `/en/schedule/`) ради простоты
    поддержки, без локализации самого слага.
-   AIOSEO апгрейд не требуется — hreflang и SEO-метаданные покрываются
    Polylang + существующим AIOSEO для sitemap/meta.

## 6. Модель контента

### Переводимые CPT (Polylang per-post translation)

`choreographer`, `styles`, `team`, `faq`, а также все шаблоны страниц
(home, camp, contact, schedule, FAQ, styles, choreographers, sign-up).
Полный паритет контента на всех 4 языках.

Featured image и произвольные поля синхронизируются между переводами
через встроенный механизм Polylang Free (Settings → Synchronizations).

### НЕ переводимые на уровне записи CPT

`locations`, `schedule` — единый источник данных (адрес, цена, время
занятий), без дублирования постов по языкам. Причина: риск
рассинхронизации цены/адреса между 4 языковыми копиями.

Для отображаемого названия города добавляются несколько дополнительных
полей на той же записи `locations` (не полноценный перевод CPT):

-   RU/UK — кириллица (Амстердам, Роттердам, Апелдорн, Арнем);
-   NL/EN — латиница как есть.

### Страница Agreement

`templates/agreement-template.php` **не переносится** в инфраструктуру
Polylang. Остаётся на своём текущем паттерне (inline `data-lang` блоки +
JS-переключатель + `localStorage`). Требуется только добавить
**украинский** как 4-й `data-lang` блок (сейчас поддерживаются
EN/NL/RU), включая:

-   hero, anchor-nav, pricing/calculator (данные филиалов `branchData`
    нужно дополнить `label_uk`), payment, SEPA, attendance,
    cancellation, company details, FAQ, CTA.

## 7. Механизм поэтапного запуска языка

-   Каждый новый язык (сначала NL, затем UK/EN) остаётся **полностью
    скрытым** через Polylang ("The language is visible online" = off) —
    не в переключателе, не индексируется поисковиками — пока не
    переведён костяк страниц:
    -   home, schedule, contact, FAQ, agreement, styles, choreographers.
-   После готовности костяка язык включается **сразу целиком**, а не
    страница за страницей.
-   Внутри уже видимого языка отдельные ещё не переведённые страницы
    (например, единичный `choreographer` без перевода) **скрываются из
    меню/переключателя языка**, а прямой заход по старой/проиндексированной
    ссылке **редиректится на RU-версию** той же страницы (без 404).

## 8. UI переключателя языка

-   Расположение: **только в шапке** (`header.php`), рядом с основной
    навигацией. В футере не дублируется.
-   Подписи: **автонимы** — Nederlands / Русский / Українська / English.
-   **Без флагов** — сознательное решение, чтобы не привязывать RU/UK к
    государственной символике.

## 9. Интеграции

### Telegram (Contact Request)

Уведомления о заявках остаются на **фиксированном русском языке**
независимо от языка страницы, с которой пришла заявка. В уведомление
добавляется поле, указывающее языковую версию сайта источника заявки.

### Mailchimp

Один общий список/аудитория для всех языков с merge-полем/тегом языка
регистрации — без отдельных списков на язык. Сегментированные рассылки
по языку возможны через фильтр по тегу.

## 10. Процесс перевода

-   Первый черновой перевод — машинный (DeepL), вне административной
    панели (Polylang Free не имеет встроенной интеграции).
-   Ручная вычитка каждого черновика по терминологии `CONTEXT.md` перед
    публикацией.
-   Готовится **глоссарий NL/RU/UK/EN** по терминам `CONTEXT.md`:
    -   `Talent Center DDC` — не переводится, используется как есть на
        всех языках;
    -   `DDC NL` — не переводится;
    -   переводятся: Dance Style, Schedule, Location, Choreographer,
        Team Member, Partner, FAQ, Agreement, Trial Lesson, Contact
        Request (последнее — только для внутренней документации, не
        публичный термин).
    -   Глоссарий фиксируется как отдельный файл рядом с этой
        спецификацией перед началом перевода контента.

## 11. Тестирование и раскатка на прод

-   Активация Polylang необратимо присваивает язык всем существующим
    записям — **сначала снимается копия продакшен-БД**, активация и
    настройка (языки, синхронизация полей, привязка CPT, меню)
    тестируется локально на XAMPP.
-   Только после локальной проверки те же шаги повторяются на
    продакшене.
-   Деплой кода темы — через FTP, как обычно (см. память проекта:
    учётные данные в `.vscode/sftp.json`), плагин Polylang — отдельная
    установка через wp-admin (не часть git-репозитория темы).
-   После изменений на проде — обязательно сбросить кэш W3 Total Cache.

## 12. Открытые зависимости / риски

-   Реальный текущий объём и состояние контента в продакшен-БД не
    проверены (локальный MySQL не был запущен на момент составления
    спеки) — уточнить перед началом реализации.
-   `page-templates/cart.php` и `checkout.php` ссылаются на WooCommerce,
    который сейчас не установлен как плагин — не в скоупе этой фичи,
    но может повлиять на структуру `page-templates/`, если тронуть
    смежные файлы.
-   Критерий "костяк переведён" (раздел 7) должен быть проверяемым перед
    включением каждого языка — зафиксировать конкретный чек-лист страниц
    на этапе реализации.

## 13. Критерии приёмки

-   Polylang Free активирован, языки RU/NL/UK/EN настроены, RU — без
    префикса и является текущим дефолтом.
-   `choreographer`, `styles`, `team`, `faq` — переводимые CPT с
    синхронизацией featured image/полей.
-   `locations`, `schedule` — без дублирования постов по языкам; у
    `locations` есть переводные поля отображаемого названия города.
-   Слаги страниц одинаковы во всех языках.
-   Hreflang-теги генерируются автоматически, `x-default` указывает на
    RU.
-   Переключатель языка — только в шапке, автонимы, без флагов.
-   NL добавлен как 4-й язык только после перевода костяка страниц;
    до этого момента скрыт полностью.
-   Непереведённые отдельные страницы не отображаются в меню/переключателе
    и редиректят на RU вместо 404.
-   `agreement-template.php` поддерживает EN/NL/RU/UK через существующий
    inline-toggle паттерн, без миграции на Polylang.
-   Telegram-уведomления остаются на русском, с меткой языковой версии
    источника заявки.
-   Mailchimp использует единый список с тегом языка.
-   Глоссарий NL/RU/UK/EN подготовлен и использован при вычитке
    переводов.
-   Активация Polylang и первичная настройка протестированы на копии
    продакшен-БД до применения на живом сайте.
